# التشغيل بالدوكر على سيرفر أوبنتو فاضي

الطريقة دي أسهل كتير من cPanel، ومش شوية — **أمر واحد** بدل حوالي أربعين خطوة.

اللي بيختفي خالص لما تسيب cPanel:

| على cPanel | بالدوكر |
|---|---|
| تثبيت Node و pnpm و PM2 و PostgreSQL بإيدك | مافيش — كله جوّه الصور |
| إنشاء النطاقات وتشغيل AutoSSL والتجديد | Caddy بيجيب الشهادات ويجدّدها لوحده |
| أربع ملفات Apache في مجلد userdata | ملف `Caddyfile` واحد، مكتوب خلاص |
| `pm2 start` و `pm2 save` و `pm2 startup` | `restart: unless-stopped` |
| مجلد صور جوّه جذر مستندات + `.htaccess` | volume مشترك |
| WHM ممكن يمسح إعدادك بصمت | مافيش WHM |
| التحديث: `git pull` + install + build + reload | `docker compose up -d --build` |

**الفرق الحقيقي مش عدد الأوامر — إنك ما بقتش بتصلّح حاجة على سيرفر حي.** الصورة
بتتبني كاملة أو بتفشل؛ ومافيش نص تركيبة شغّالة على السيرفر.

---

## اللي محتاجه

- سيرفر أوبنتو ٢٢.٠٤ أو ٢٤.٠٤، **٤ جيجا رام على الأقل** (البناء نفسه هو
  الجزء التقيل، مش التشغيل)، و٢٠ جيجا مساحة
- IP ثابت، والبورتات ٨٠ و٤٤٣ مفتوحة
- النطاقين مأشّرين على الـ IP ده **قبل ما تبدأ**

النقطة الأخيرة دي مش تفصيلة: Let's Encrypt بيتحقق إن السيرفر ده فعلاً بتاع
النطاق عن طريق طلب على بورت ٨٠. لو الـ DNS لسه ما انتشرش، إصدار الشهادة بيفشل
وCaddy بيفضل يحاول.

اتأكد الأول:

```bash
dig +short ihotel.planova.com.eg
dig +short ihotel-admin.planova.com.eg
```

الاتنين لازم يرجّعوا IP السيرفر.

## ٣. `.env`

```bash
./infra/docker/setup-env.sh \
  ihotel.planova.com.eg \
  ihotel-admin.planova.com.eg \
  you@planova.com.eg
```

بيولّد الأسرار ويكتب الملف ويقفل صلاحياته على `600`، وبيرفض يكتب فوق `.env`
موجود.

**السبب إن ده سكريبت مش خطوة يدوية:** compose بيتعامل مع القيمة الفاضية زي
المفقودة بالظبط. يعني مفتاح سايبه `""` بيفشل بنفس رسالة مفتاح مش مكتوب أصلاً،
والرسالة بتقولك اسم المتغير من غير ما تقولك إنه قاعد في الملف قدامك، فاضي.

لو عايز تكتبه بإيدك: `cp .env.docker.example .env` وبعدين املا الست دول —
**ومحدش فيهم يفضل فاضي**:

```bash
PUBLIC_DOMAIN="ihotel.planova.com.eg"
ADMIN_DOMAIN="ihotel-admin.planova.com.eg"
ACME_EMAIL="ana@planova.com.eg"

POSTGRES_PASSWORD="…"     # openssl rand -hex 24
AUTH_SECRET="…"           # openssl rand -hex 32
REVALIDATE_SECRET="…"     # openssl rand -hex 24
```

`hex` مش `base64`: الـ base64 بيطلّع `+` و `/` و `=`، ودي محتاجة تنصيص صح في
ملف `.env` وسهل تتلخبط وهي بتتنسخ في التيرمينال.

مافيش `DATABASE_URL` ولا `MEDIA_ROOT` ولا بورتات ولا مسارات سجلات — دول كلهم
اتحسبوا في `docker-compose.yml`. **كل مسار كان ممكن تغلط فيه على cPanel مابقاش
موجود أصلاً.**

## ٤. شغّله

```bash
docker compose up -d --build
```

خلاص. الأمر ده بيعمل:

1. يبني الصورة — تنصيب الحزم، توليد Prisma، بناء التطبيقين
2. يقوّم PostgreSQL ويستنى لحد ما يبقى جاهز
3. يشغّل الميجريشن، ولو قاعدة البيانات فاضية بيزرع المحتوى والصور
4. يشغّل الموقع ولوحة التحكم والعامل الخلفي
5. يقوّم Caddy، اللي بياخد شهادات للنطاقين من Let's Encrypt
6. يسخّن الصفحات المخزّنة عشان أول زائر ما يشوفش صفحة فاضية

**أول مرة بتاخد من ١٥ لـ ٢٥ دقيقة** — البناء وحده حوالي عشرة، وزرع الصور بيرسم
٣٣ صورة (كل واحدة أربع مقاسات في صيغتين، يعني حوالي ٢٦٠ عملية ترميز). المرات
اللي بعدها دقيقتين.

اتفرّج وهو شغّال:

```bash
docker compose logs -f release
```

## ٥. اتأكد إنه شغّال

```bash
docker compose ps
```

المفروض تشوف `db` و`web` و`admin` و`worker` و`caddy` شغّالين، و`release`
و`warmup` واقفين بعد ما خلّصوا شغلهم — **ده طبيعي، مش خطأ**.

وبعدين في المتصفح، بالترتيب ده:

1. `https://ihotel.planova.com.eg/en` — الموقع طالع، الصور بتظهر، والقفل ظاهر
2. `https://ihotel.planova.com.eg/ar` — عربي من اليمين لليسار
3. تواريخ ← بحث ← غرفة ← بياناتك ← **ادفع** ← لازم توصل لصفحة تأكيد فيها رقم
   مرجع `FNT-…` ورقم تأكيد فندق
4. `/en/my-booking` — رقم المرجع + الإيميل بيلاقوا الحجز
5. `https://ihotel-admin.planova.com.eg` — ادخل `admin@fantazia.test` /
   `fantazia-dev`، والحجز اللي عملته لازم يكون في **Bookings**

الخطوة ٣ هي المهمة: هي لوحدها بتتحقق من البحث والإتاحة والتسعير والحجز المؤقت
والدفع والـ webhook وإنشاء الحجز — السلسلة كلها.

**غيّر الباسورد ده فوراً.** هو مكتوب في المستودع العام. من Staff ← حسابك، وشغّل
الدخول بخطوتين وإنت هناك.

## ٦. امنعه من جوجل

نسخة عرض مفهرسة جنب الموقع الحقيقي بتنافسه على نفس البحث. لحد الإطلاق، ضيف
السطر ده جوّه بلوك `{$PUBLIC_DOMAIN}` في `infra/docker/Caddyfile`:

```
header X-Robots-Tag "noindex, nofollow"
```

وبعدين `docker compose restart caddy`.

**`X-Robots-Tag` مش `robots.txt`** — التاني بيمنع الزحف بس العنوان لسه ممكن
يظهر في النتائج لو حد لينك عليه.

لوحة التحكم متعلّمة `noindex` أصلاً.

cd /opt/fantazia

## الأوامر اللي هتحتاجها

```bash
docker compose ps                      # مين شغّال
docker compose logs -f web             # سجلات الموقع
docker compose logs -f worker          # إعادة المحاولة والإيميلات
docker compose restart web             # إعادة تشغيل واحد
docker compose down                    # وقّف الكل (البيانات بتفضل)
docker compose exec db psql -U fantazia   # ادخل على قاعدة البيانات
```

نسخة احتياطية:

```bash
docker compose exec -T db pg_dump -U fantazia fantazia | gzip > backup-$(date +%F).sql.gz
docker run --rm -v fantazia_media:/m -v "$PWD":/out alpine \
  tar czf /out/media-$(date +%F).tar.gz -C /m .
```

حطهم في cron يومياً وإنت مغطّى: التنين دول فيهم كل حاجة مش موجودة في git.

## حاجات لازم تعرفها

**تغيير النطاق محتاج إعادة بناء، مش إعادة تشغيل.** Next بيحقن
`NEXT_PUBLIC_SITE_URL` جوّه ملفات الجافاسكريبت وقت البناء. غيّرته في `.env`؟
شغّل `docker compose up -d --build`.

**الشهادات في volume اسمه `caddy_data`.** لو مسحته هتتصدر من الأول، ولو عملت
كده كذا مرة في اليوم Let's Encrypt هيوقّفك مؤقتاً. `docker compose down` عادي
ما بيمسحش volumes؛ **`docker compose down -v` بيمسحهم** — ده الأمر اللي بيمسح
قاعدة البيانات والصور والشهادات كلهم مرة واحدة.

**`ALLOW_TEST_PAYMENTS="yes"` مسموح بيها هنا لأن دي نسخة عرض.** صفحة الدفع
بتنجح دايماً. **امسح السطر ده قبل ما الموقع يبقى حقيقي.**

**الصور مش في git.** الزرع بيرسمها على السيرفر — بشكل حتمي، نفس الأسماء بتدّي
نفس الصور. كلها متعلّمة `isPlaceholder` وبتتشال بـ:

```bash
docker compose run --rm release pnpm --filter @fantazia/db seed:demo -- --clear
```

**العامل الخلفي مش اختياري.** من غيره الحجوزات اللي دفعت وفشل تأكيدها ما
بتتعادش المحاولة فيها، والإيميلات بتفضل في الطابور ومحدش بيستلمها.

## لما دي تبقى الموقع الحقيقي

**مش هجرة — نسخة تانية.** سيب دي شغّالة، وقوّم نسخة الإنتاج جنبها في مجلد تاني
بـ `name` مختلف في `docker-compose.yml` وقاعدة بيانات منفصلة، وبعدين حوّل الـ
DNS. نظامين شغّالين ليوم واحد رخيص؛ نظام واحد اتنقل نص نقلة لأ.

**وقبل اليوم ده بمدة:** الموقع الحالي على `fantaziaresorts.com` عنده عناوين
جوجل مفهرسها. عناوين الموقع الجديد شكلها مختلف — كل مسار بياخد `/en` أو `/ar`.
من غير تحويلات، كل لينك من دول هيبقى ٤٠٤ وترتيب البحث هيروح معاه. الشغل ده
**لسه متعملش**، ومحتاج قائمة عناوين الموقع القديم عشان يبدأ — من `sitemap.xml`
بتاعه أو من Google Search Console ← Pages.
