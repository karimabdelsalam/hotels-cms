# التشغيل على نطاق فرعي، جنب الموقع الشغّال

مكتوب لـ **`ihotel.planova.com.eg`**، وده المكان اللي المشروع رايحه أول مرة.
لو النطاق اتغيّر، بدّل الأسماء — مافيش حاجة في الخطوات دي معتمدة على الاسم نفسه.

ده مش دليل الإطلاق. ملف `deployment.md` بيغطّي الاستحواذ على النطاق الرئيسي.
الملف ده بيغطّي تشغيل المنصة **جنب** اللي موجود دلوقتي: كل حاجة حقيقية قدامك
تتفرّج عليها، ومافيش أي حاجة معرّضة للخطر.

| | المستخدم في كل الخطوات |
| --- | --- |
| حساب cPanel | `planova` — **تأكّد منه**، هو صاحب `planova.com.eg` |
| الموقع العام | `ihotel.planova.com.eg` |
| لوحة التحكم | `ihotel-admin.planova.com.eg` |
| اسم النسخة | `ihotel` — بيسمّي عمليات PM2 ومجلد السجلات |

**اسم حساب cPanel هو الحاجة الوحيدة هنا اللي لازم تتأكد منها بنفسك مش تنسخها.**
اكتب `whoami` في تيرمينال cPanel، أو شوف WHM ← **List Accounts**.

## الشكل النهائي

```
ihotel.planova.com.eg         →  الموقع العام       Node على 127.0.0.1:3100
ihotel-admin.planova.com.eg   →  لوحة التحكم        Node على 127.0.0.1:3101
                                 العامل الخلفي      بدون بورت — إعادة المحاولة والإيميلات

planova.com.eg                →  ما اتلمسش
fantaziaresorts.com           →  ما اتلمسش، لسه موقعكم الشغّال
```

**البورتات ٣١٠٠ و ٣١٠١، مش ٣٠٠٠ و ٣٠٠١.** ممكن يكون فيه حاجة على السيرفر
شغّالة على المعتادين، وتضارب البورت بيظهر كموقع شغّال بيقدّم **تطبيق تاني** —
وده بياخد ساعة عشان تفهمه. وكمان بيسيب المعتادين فاضيين عشان نسخة الإنتاج
تشتغل جنب دي وقت التحويل.

**ملحوظة:** لا يوجد أي عملية Node بتسمع على واجهة عامة. Apache هو الوحيد
المربوط على ٨٠ و ٤٤٣، و PostgreSQL على localhost بس.

## ١. النطاقين الفرعيين

من **cPanel ← Domains ← Create A Domain**، مرتين.

أنشئ `ihotel.planova.com.eg` و `ihotel-admin.planova.com.eg` على **نفس الحساب
الموجود**. cPanel هيقترح جذر المستندات `/home/planova/ihotel.planova.com.eg` —
وافق عليه. نفس الحاجة للتاني.

**ما تعلّمش على** "Share document root with the main domain".

بعدين **cPanel ← SSL/TLS Status**، اختار النطاقين الجداد، واضغط **Run AutoSSL**.

**استنى الشهادات قبل ما تكمّل.** التطبيق بيبعت هيدر HSTS، والمتصفح اللي يقابل
HSTS مع شهادة فيها مشكلة هيرفض يفتح الموقع لحد ما مدة الهيدر تخلص — يعني ممكن
تفضل مقفول عليك أسابيع.

## ٢. أماكن الملفات

```
/home/planova/ihotel-app                          المستودع        ← مش جذر مستندات
/home/planova/ihotel.planova.com.eg/media         الصور           ← Apache بيقدّمها مباشرة
/home/planova/ihotel-backups                      النسخ الاحتياطية
/var/log/ihotel                                   سجلات PM2
```

**المستودع ما يكونش جوّه أي جذر مستندات — دي أهم تفصيلة في الملف كله.**
أي حاجة تحت جذر المستندات ممكن تتحمّل عبر HTTP، والمستودع ده فيه ملف `.env`:
باسورد قاعدة البيانات، ومفتاح الجلسات، وبيانات اعتماد أوبرا بعدين. وضع المشروع
في جذر المستندات معناه نشر التلاتة على الإنترنت.

الصور جوّه جذر المستندات هي الحالة العكسية وبقصد: Apache بيقدّم المجلد ده أصلاً،
فالصور مش محتاجة أي إعداد و **Node ما بيشوفش طلب صورة أبداً**.

```bash
mkdir -p /home/planova/ihotel-app /home/planova/ihotel-backups
mkdir -p /home/planova/ihotel.planova.com.eg/media
mkdir -p /var/log/ihotel
chown -R planova:planova /home/planova /var/log/ihotel
```

مافيش حاجة في مجلد الصور يُسمح لها تتنفّذ — ده مجلد الجمهور بيكتب فيه من خلال
نموذج الرفع:

```apache
# /home/planova/ihotel.planova.com.eg/media/.htaccess
Options -Indexes -ExecCGI
RemoveHandler .php .phtml .php3 .php4 .php5 .php7 .php8 .cgi .pl
php_flag engine off
Header always set Cache-Control "public, max-age=31536000, immutable"
Header always set X-Content-Type-Options "nosniff"
```

## ٣. Node و pnpm و PostgreSQL

كـ **root**. لو السيرفر شغّال عليه أي واحد فيهم لحاجة تانية، **اتأكد من النسخة
بدل ما تعيد التثبيت** — ممكن تكسر حاجة شغّالة.

```bash
# Node 22 — AlmaLinux / CloudLinux
dnf module reset nodejs -y && dnf module enable nodejs:22 -y && dnf install -y nodejs

# Node 22 — Ubuntu
curl -fsSL https://deb.nodesource.com/setup_22.x | bash - && apt-get install -y nodejs

corepack enable && corepack prepare pnpm@10 --activate
npm install -g pm2
```

PostgreSQL 16، بيسمع على localhost بس:

```bash
# AlmaLinux / CloudLinux
dnf install -y postgresql16-server postgresql16-contrib
/usr/pgsql-16/bin/postgresql-16-setup initdb
systemctl enable --now postgresql-16

# Ubuntu
apt-get install -y postgresql-16
```

```bash
sudo -u postgres psql <<'SQL'
CREATE USER ihotel WITH PASSWORD 'حط-باسورد-طويل-وعشوائي-هنا';
CREATE DATABASE ihotel OWNER ihotel;
SQL
```

**قاعدة بيانات منفصلة عن أي نسخة إنتاج مستقبلاً.** مشاركة قاعدة واحدة بين
تجربة الناس بتضغط فيها وأي حاجة حقيقية هي الطريقة اللي بيها حجوزات وهمية توصل
لتقرير آخر الشهر.

اتأكد إن `listen_addresses = 'localhost'` في `postgresql.conf`. PostgreSQL
ما يكونش موصول من برّه السيرفر.

## ٦. قاعدة البيانات، وبعدين المحتوى

```bash
cd /home/planova/ihotel-app

pnpm --filter @fantazia/db exec prisma generate
pnpm --filter @fantazia/db exec prisma migrate deploy

pnpm db:seed                              # البنية والأدوار والموظفين ونصوص الواجهة
pnpm --filter @fantazia/db seed:booking   # خطط الأسعار والسياسات و١٢٠ ليلة إتاحة
pnpm --filter @fantazia/db seed:demo      # النصوص التجريبية و٣٣ صورة مولّدة
```

**الصور مش في الـ git ومش محتاجة تكون.** الأمر الأخير بيرسمها على السيرفر —
بشكل حتمي، يعني نفس الأسماء بتدّي نفس الصور بالظبط. بياخد كام دقيقة: ٣٣ صورة كل
واحدة بتبقى أربع مقاسات في صيغتين، يعني حوالي ٢٦٠ عملية ترميز.

كل اللي بيكتبه متعلّم بـ `isPlaceholder`، وبيظهر كده في مكتبة الصور، وبيتشال
بأمر واحد:

```bash
pnpm --filter @fantazia/db seed:demo -- --clear
```

## ٧. البناء والتشغيل

```bash
pnpm build
```

بعدين شغّل التلات عمليات. **مافيش أي ملف بيتنسخ أو يتعدّل** — ملف
`infra/ecosystem.config.cjs` بيقرا البورتات والأسماء ومسار السجلات من البيئة
(اللي حطيتها في `.env`)، فالفرق بين نسخة العرض ونسخة الإنتاج أربع سطور مش ملف
منفصل بيبطّل يستقبل الإصلاحات.

```bash
set -a && source .env && set +a     # PM2 محتاجهم في بيئته هو
pm2 start infra/ecosystem.config.cjs
pm2 save
pm2 status
```

```bash
# كـ root، مرة واحدة — بيكتب وحدة systemd بتعيد تشغيل القائمة بعد إعادة التشغيل
pm2 startup systemd -u planova --hp /home/planova
```

**لازم التلات عمليات تكون `online`.** العامل الخلفي مش اختياري: من غيره،
الحجوزات المدفوعة بتبطّل إعادة المحاولة وإيميلات التأكيد ما بتتبعتش خالص.

```bash
curl -sI http://127.0.0.1:3100/api/health
curl -sI http://127.0.0.1:3101/api/health
pm2 logs ihotel-worker --lines 20
```

## ٨. إعداد Apache

لازم `mod_proxy` و `mod_proxy_http` و `mod_headers` و `mod_rewrite` يكونوا
مفعّلين — **WHM ← Software ← EasyApache 4**. معظم الملفات الجاهزة فيها.

**الإعداد بيتحط في مجلد userdata، مش في vhost.** WHM بيعيد توليد الـ vhosts مع
أي إعادة بناء لـ Apache، وهيمسح أي تعديل هناك **بصمت**، وعادةً في أسوأ وقت.

فيه أربع ملفات لازم تتكتب — نطاقين × عادي و SSL — كل واحد محتاج اسم الحساب
ومسار المشروع والبورت الصح. عملها بإيدك أكتر خطوة معرّضة للغلط، والغلط فيها
**بيحصل بصمت**: بورت غلط بيودّي ترافيك لوحة التحكم للموقع العام، ومسار غلط
بيخلي `/_next/static` ترجّع ٤٠٤ فالموقع يفتح من غير أي تنسيق.

السكريبت بيعمل التبديل ويتحقق من النتيجة:

```bash
# كـ root
/home/planova/ihotel-app/infra/apache/install.sh \
  --user    planova \
  --app     /home/planova/ihotel-app \
  --public  ihotel.planova.com.eg       --public-port 3100 \
  --admin   ihotel-admin.planova.com.eg --admin-port  3101
```

بيرفض يشتغل لو المشروع مش مبني، أو لو مجلد userdata مش في المكان المتوقع، أو لو
فضل أي placeholder بعد التبديل. وبيشغّل `ensure_vhost_includes` و
`apachectl configtest` لوحده.

```bash
systemctl restart httpd
```

اتأكد من مسار userdata حسب نسخة cPanel عندك — **WHM ← Apache Configuration ←
Include Editor** بيوريك المكان المتوقع. لو مختلف، مرّره بـ `--userdata`.

الملفات دي بتستثني `/media` و `/_next/static` من الوكيل بـ `ProxyPass … !`،
فـ Apache بيقدّمهم من القرص و **Node ما بيشوفش طلب ملف ثابت**.

## ١٠. امنعه من جوجل

نسخة عرض مفهرسة جنب الموقع الحقيقي بتنافسه على نفس عمليات البحث وبتقسّم
الترتيب بينهم. لحد الإطلاق:

```apache
# /home/planova/ihotel.planova.com.eg/.htaccess
Header always set X-Robots-Tag "noindex, nofollow"
```

**`X-Robots-Tag` مش `robots.txt`.** ملف robots.txt بيطلب من الزواحف ما تجيبش
الصفحة، وده **ما بيمنعش** العنوان يظهر في نتائج البحث لو حد لينك عليه. الهيدر
بيقولهم ما تفهرسوش، وده اللي بيمنعه فعلاً.

وحمايته بباسورد من **cPanel ← Directory Privacy** أقوى، ويستاهل لو العرض
للفريق بس.

## لما دي تبقى الموقع الحقيقي

**مش هجرة للنسخة دي — نسخة تانية.**

سيب دي شغّالة، وابني نسخة الإنتاج جنبها على ٣٠٠٠/٣٠٠١ بقاعدة بيانات وحساب
منفصلين، وبعدين حوّل الـ DNS. نظامين شغّالين ليوم واحد رخيص؛ نظام واحد اتنقل
نص نقلة لأ.

**وقبل اليوم ده بمدة:** الموقع الحالي على `fantaziaresorts.com` عنده عناوين
جوجل مفهرسها ومواقع تانية بتلينك عليها. عناوين الموقع الجديد شكلها مختلف — كل
مسار بياخد `/en` أو `/ar`. من غير تحويلات من العناوين القديمة للجديدة، كل لينك
من دول هيبقى ٤٠٤ وترتيب البحث هيروح معاه.

الشغل ده **لسه متعملش**، ومحتاج قائمة عناوين الموقع القديم عشان يبدأ —
من `sitemap.xml` بتاعه أو من Google Search Console ← Pages.
