Content pages are block-based. Editors compose them from the same components the homepage uses, so a new page cannot drift away from the design system. The /{slug} catch-all is matched last, so a page can never shadow a booking route.

This screen is a working prototype. Add, remove, reorder, nest, rename, and switch between the five menus — the preview updates live. Nothing persists; Save is a demonstration.

Try the two behaviours that matter. The Destinations item in the primary menu is greyed because its module is switched off, and Press under Pages is a draft — neither renders in the preview, and neither can become a broken link. Add them and see. This is what lets you keep a menu item ready for a resort that opens next season without it leaking onto the live site.

Labels are per language, structure is shared. Switching the label language changes the words, never the tree — so the site cannot end up with a different information architecture in German than in English, which is what happens when each language gets its own menu and becomes unmaintainable past two.
